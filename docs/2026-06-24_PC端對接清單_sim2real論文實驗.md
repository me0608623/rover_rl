## A. 受控對照模型（最關鍵）

現況：**SA1~SA7 是漸進 curriculum，沒有任何一個是真正的 clean baseline**。SA1 雖 `lidar_no_noise=true`，但 distance_bias、per_ring_bias、physics DR、actuator DR **全程 ON** → 不能當對照組。

需新訓一個 **clean baseline**，採以下定義（**方案二，建議**）：

### 方案二（建議）：只關「LiDAR 雜訊建模 + LiDAR DR」，physics/actuator DR 兩邊都保留
論文賣點是「LiDAR 雜訊建模」，這樣才能乾淨歸因；physics/actuator DR 維持開啟、兩個模型相同，不污染變數。

```yaml
# ===== clean baseline：LiDAR 端全關 =====
lidar_no_noise: true              # L1 隨機雜訊全關（displacement/hole/distractor/soft）
distance_bias_k_dr: [0, 0]        # 關距離偏差 DR
distance_bias_b_dr: [0, 0]
per_ring_bias: false              # 關 per-ring 偏差
obs_noise_std: 0.0                # L2 GaussianNoise 關
block_dropout_prob: 0.0           # L2 block dropout 關
# L3 per-episode DR 不啟用（k_σ/p_hole/σ_soft 不重採樣）

# ===== 以下兩個模型「完全相同、都保留」=====
# physics_mass_dr / physics_friction_dr / physics_com_offset：照常 ON
# actuator DR：delay_range / velocity_scale / motor_lag / obs_delay_steps 照常 ON
# wind/push 擾動：照常 ON
```

### 方案一（備選）：雜訊+所有 DR 全關（連 physics/actuator 也關）
最戲劇化（「完整方法 vs 全乾淨 sim」），但 LiDAR 雜訊與 physics/actuator DR 兩因子混在一起，無法歸因到「LiDAR 雜訊建模」。**除非你只想要一張漂亮的總對比圖，否則不建議。**

### 兩模型唯一差異 = 上面那組 LiDAR 開關；其餘逐項相同
- 同 scene / curriculum 終點 / reward / 網路架構 / obs 維度（79/83/139 全程一致）
- 同 action space 與動作上限、同 control_dt(0.2s)、同 episode_horizon
- **同訓練步數**：用收斂值（如 240k）。⚠ 別給低 step（車端實測低 step 模型會無關雜訊地蛇行 ±0.6rad/s @0.31Hz，變成混淆變數）。
- 理想：clean 與 noisy **各 2~3 seed**。

### 匯出與交付
- `scripts/export_policy.py`（auto-detect 架構）匯出，**務必帶 obs_normalizer 的 checkpoint**。
- ⚠ clean 與 noisy **各自用各自訓練出的 normalizer**（obs 統計不同，不可共用）。
- 命名：`<scene>_noisy_dr_240000.ts` / `<scene>_clean_240000.ts`，scp 到車端 `~/rover_rl/models/`。
- 附一行：obs 維度、ω 上限、r_min/r_max、episode_horizon（車端要對應 yaml）。

### A2. 確認 deployed noisy 模型
車端目前 models/ 有 `sa4_v3f_240000.ts` 等。請明確：**部署比較要用哪一支當 noisy+DR 組**、它是哪個 SA config / 哪個 scene（T-corridor? v3c 牆壁+crossing?）。clean baseline 必須訓在**同一 scene**，否則場景差異會混淆雜訊效果。

## C. sim eval 的 obs/sweep 日誌（E2 分布橋接，最加分、你筆記還沒做）

車端要畫「真機 obs 分布 vs clean-sim vs noisy-sim」證明 covariate shift。你既有筆記只有 sensor 端常態檢定，**沒有 sim↔real 分布距離（KL/Wasserstein）**，這塊是新增重點。

### 怎麼做
- 對 **clean baseline** 與 **noisy+DR** 模型各跑 sim eval rollout。
- 每 timestep dump **72-bin sweep（policy 實際輸入）**；理想連同完整 obs + action。
- ⚠ noisy 那批要記「**加噪後、policy 實際看到的** sweep」，不是 clean ground truth。
- 每 episode 一檔（npz/csv），檔名含 model/場景/episode；跨多場景數十 episode。
- scp 給車端 → 車端算三組 KL / JS / Wasserstein + 每 bin 直方圖 + 掉點率（bin=1.0 比例）+ Δsweep 抖動。

## 已核實事實（來自你 Obsidian 筆記，PC 端不必再提供）

> 以下車端已從《LiDAR Sim-to-Real（一)~(四)》確認，列此供雙方對齊、避免重複問。

### 雜訊數學模型（已校準、已實作）
- **距離雜訊**：`σ(d)=0.000117·d + 0.000535` m（10 點實測擬合，R²=0.29，距離相依弱）。**舊值 0.00036 已淘汰**；訓練 DR 用 `k_σ ~ U(0.0002, 0.0006)`。
  - ⚠ 車端 `lidar_preprocess.py:10-12` 註解還寫 0.00036（stale），論文勿引此行。
- **掉點**：`P_dropout(d) ≈ 0.18 + 0.02·d`（0.5m→19%、5m→28%）；訓練 `p_hole ~ U(0.15,0.30)`。
- **distractor/假回波**：0.2%，假距離 U(0.2,2.0)m。
- **人體 soft-target**：σ 18~123mm（比白牆大 15~300×），多峰，用 `σ_soft ~ U(0.002,0.020)` RSS 疊加。
- **系統 bias**（未實作，見 B 項）：distance_bias(k≈−0.015, b≈+0.030, ±30mm)、per_ring_bias(16通道 ±22.7mm)。

### 三層注入架構（已實作）
- **L1 per-ray（min-pool 前，raw 距離）**：Gaussian displacement、hole dropout、distractor、σ_soft。
- **L2 per-bin（min-pool + 正規化後 72 維）**：GaussianNoise σ=0.005、block dropout（連續 3~8 bins）。
- **L3 per-episode**：每回合重採樣 L1 參數（SA5+ 啟用）。
- 管線：`5760 rays →[L1]→ min-pool → normalize →[L2]→ clip → 72D`。

### SA1~SA7 = 漸進 curriculum（非乾淨對照）
- SA1：lidar_no_noise，但 bias/physics/actuator DR ON（最接近 clean，仍非 clean）。
- SA2：50% 噪聲、bias 暫關。SA3+：100% 噪聲 + block dropout。SA5+：L3 per-episode DR + σ_soft。SA7：全拉滿。
- physics DR(mass U0.85-1.15 / friction U0.7-1.3 / com ±5cm)、actuator DR(delay / velocity_scale / motor_lag) **SA1-7 全程 ON**。
